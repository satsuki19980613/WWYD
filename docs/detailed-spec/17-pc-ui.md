# 17. PC の UI（2026-09-29）

さつきの依頼「現状ほぼスマホ用で構成されているので PC の UI はかなり弱め。PC の UI として完璧なものを求める。まずネットリサーチで参考となるアプリの UI・UX の特徴を調べ、そこから改修する。
ヒストリー登録のハンドの登録時のキーボードはスマホ用なので、PC ではハンド選択ボードでよい」の記録。
06 章（画面）・09 章（ⓘ の文言）にも反映した。スマホ（700px 未満）の構成は変えていない。

## 1. 調べたもの

14 章（スマホ中心の調査）に続けて、**デスクトップ版**の画面の組み方を調べた。公開のヘルプ・マニュアル・ソース（Lichess の SCSS）を読んだ。
取得できなかったもの（GTO+ のマニュアル、Run It Once Vision のガイド、Hand2Note のマニュアル、Equilab の記事など）は使っていない。

| 性質 | 調べたもの |
|---|---|
| ポーカーの学習ツール | GTO Wizard（Study・Range Builder・Trainer・Analyzer）、PioViewer、Flopzilla、PokerTracker 4 と Holdem Manager 3 のリプレイヤー、PT4・DriveHUD・PokerCharts のエクイティ計算機（カードの入力） |
| 答えてから比べる・手順を再生する | Lichess（Puzzle・Analysis の列の組み方とキー操作）、Chess.com の Analysis、LeetCode の分割画面 |
| 一般の原則 | NN/g（画面幅・視線は左に寄る・アクセラレータ・ツールチップ）、Microsoft の List/details、Material 3 の画面幅の区分、MDN の setPointerCapture、GitHub のショートカット |

## 3. 画面ごとの変更（PC = 700px 以上）

### 3.1 ヘッダー

- 左に **List** と **＋ Post** のナビ（いまいる項目は黄。＋ Post は黄の枠の面取り、Post の画面では黄の実面）。PC は「＜」（一覧へ）を出さない（ナビで戻れる）。
- ナビに無い画面（回答・結果・下書き・規約）は、ナビの右に「/ 回答」のように画面名を出す。List・Post の画面名は読み上げだけに残す（h1）。
- 一覧の「＋ Post」のボタンは、ナビにあるので PC の一覧からは外した（スマホは下の固定ボタンのまま）。

### 3.2 一覧

- 左に絞り込みの列（200px。1200px 未満は 160px）: 範囲（すべて / 自分の投稿）・Street・並び替え。上から縦に並べ、選択中は左の黄の線。
- 右に 1 行 1 投稿の表: Street ｜ Title（下に「自分の投稿」「回答済み」）｜ Game ｜ Hero ｜ 回答 ｜ 投稿 ｜ 回答する・結果を見る（と削除）。見出しは画面に固定。
- 行全体を押せる。見出しの「回答」「投稿」を押すと並び替え（左の列と同じ）。↑ ↓（j k）で行を移り、Enter で開く。1200px 未満は Game の列を隠す。

### 3.3 回答・集計

- 1200px 以上は 3 列で、画面の高さに収める（ページはスクロールしない）:
  - 左: メタ情報・タイトル・卓（残りの高さを使う）・再生の操作・Hand History（高さを抑えてスクロール）。
  - 中央: レンジ表（正方形。画面の高さ・760px・幅の残りのうち最小。1440×900 で 648px）。集計は上に表示の切り替え。
  - 右（300px）: 回答はブラシ・Size・下部のバー・送信。集計は答え合わせ・全体と自分のバー・マスの内訳・削除・次の Spot。
- 1200px 未満は 2 列（左にリプレイ、右にレンジ表と道具。ページをスクロール）。
- キー: ← → で 1 手、Home で最初、End で最後（回答は Spot）。表のマスを選んでいるときの矢印は表が使う。入力欄・モーダルの操作中は効かせない。
- 回答: Ctrl+Z で元に戻す、Ctrl+Y・Ctrl+Shift+Z でやり直す、B でブラシ、E で消しゴム。
- 集計: マスにマウスを乗せると内訳がそのマスになる。押す・キーで選ぶと固定。

### 3.4 投稿（ハンドの入力）

- **PC は Hand 欄を押すと Card の選択ボード（ダイアログ）を開く**（スマホは従来の Card キーボード）。
  上に選んだ 2 枚、下に 4 段（♠ ♥ ♦ ♣）× 13 列（A〜2）。ほかの席とボードで使った札は押せない。
  - 札を押すと足す。選んである札を押すと外す。2 枚そろっていれば 2 枚目を置き換える（`pickCard`）。
  - 2 枚そろうと、次の Hand が空の席へ進む（`nextOpenSeat`。空の席が無ければそのまま）。
  - キーでも打てる（`A` → `s`。Backspace で 1 文字、Delete で全部）。← → で前後の席、Enter で閉じる。
  - OCR の読み取り結果の画面でも同じ（PC）。ボードのカードピッカーも同じ幅（最大 720px）のダイアログにした。
- 1200px 以上は 3 列（基本設定・Player ｜ 卓と Action ｜ Spot・タイトル・投稿する）。右の列はスクロールしても見える位置に固定。
  1200px 未満は 2 列（左に基本設定・Player・Spot、右に卓と Action）。
- Ctrl+Z で Action を 1 つ戻す、Ctrl+Y・Ctrl+Shift+Z で 1 つ進む。

## 4. 採らなかった型

| 型 | 理由 |
|---|---|
| ボタンのツールチップ・キーの表示（kbd のバッジ） | 画面に説明を出さない（不変条件 1）。ⓘ に集約した |
| 一覧の右のプレビューの列 | 集計は回答するまで見せない（不変条件 10）ので、出せるのは一覧の行と同じ情報だけになる |
| レンジ表の右クリック・ホイールでの頻度の増減 | ブラウザのメニューを止めることになり、発見もしにくい。既存の道具（消しゴム・ミックスバー）で足りる |
| 左の常設のナビ | 画面が 4 つしかない |
| 投稿の縦のステッパー | PC は全部の欄を同時に出しており、順番を強いる必要がない |
