# 14. 類似アプリの調査と UI・UX への反映（2026-09-29）

さつきの依頼「ネットリサーチで、このプロジェクトと性質が共通するアプリの UI や UX の特徴を調査してこのアプリに反映する」の記録。
調べた範囲、採った型、採らなかった型とその理由、画面ごとの変更を書く。変更の細部は 06 章・13 章・09 章にも反映した。

「3 秒で入力」などの数値は各社の宣伝で、独立した測定は見つからなかった）。

## 3. 画面ごとの変更

### 3.1 スポット投稿のアクション（13 章 §6）

- 入力中のハンドを**卓**で出す（回答画面と同じ部品）。Hero を手前、手番の席を黄のグロー、各席のスタック・直前のアクション・ベットのチップ、
  中央にポットとボード。ボードの 5 枠は卓の中にあり、次に要る枠の「＋」でピッカーを開き、カードを押すとそのカード以降を消す（前と同じ）。
  終わったら卓の中央に「{席} ポット獲得」か「ショーダウン」、カードの無い席は「マック」。前の「終了表示」の枠はやめた。
- ログは回答画面と同じ形（ストリートごとの列、席の色）。**ログの 1 手を押すと「{手} から入れ直しますか」**の確認のあと、その手から後のアクションを消す（ボードは残す。1つ戻すと同じ）。
- 台のボタンの名前: プリフロップは「オープン」→「3bet」→「4bet」…（リンプがいれば最初は「レイズ」）、BB 以外のリンプは「リンプ」。
  フロップ以降は「ベット」→「レイズ」→「3bet」…。ログ・ハンドヒストリーの表記は今までどおり（レイズ・コール）。

#### さつきの確認を受けての直し（2026-09-29）

- スマホのログは常に出さず（アクションが増えると画面を圧迫する）、卓の左上の空きに「ヒストリー」のボタンを置き、押すとモーダルで開く。
  モーダルの 1 手を押すと、モーダルを閉じて入れ直しの確認を出す。
- 台の見出しの行（席・ストリート・POT・残り・1つ戻す）と「すべて消す」を、台の空きに収めた: よく使う額 →（Fold to）→ **道具の行**
  （手番・1つ戻す・**1つ進む**・すべて消す（確認あり）・額）→ 3 つのボタン。POT・残りは卓に出ているので外した。台の高さは前の「額の行＋入力欄の行＋ボタン」と同じ。
- 額の欄はスマホでは押すと**縦のスライダー**（キーボードで画面を圧迫しない）。詳細は 06 章 §3.6。
- ログが卓の下から無くなった分、スマホの卓を画面の高さに合わせて大きくした（300〜400px）。
- よく使う額がオールインだけのときは、その行を出さない（額の欄の最大と同じで、台が高くなるだけ）。

### 3.5 下書き（さつきの指示。2026-09-29）

入力の途中で投稿の画面を離れると、入力がそのまま残って次に開いたときに出ていた。1 人 3 件までの下書きに作り直した（06 章 §3.2）。
保存先は端末のブラウザ（さつきの決定。DB の変更が要らず、入力途中の Hero のハンドがサーバーに出ない。別の端末とは共有されない）。
ヘッダーの右の下書きのボタン → 下書きの画面で選ぶ。離れるときに「下書きに保存しますか」、いっぱいならどれかを消すダイアログ。

### 3.6 そのほか（さつきの指示。2026-09-29）

- 画面のポーカー用語をすべて英単語に（15 章）。
- 回答のリプレイ・集計の Hand History（スマホ）もログをモーダルに（卓の左上の「History」）。空いた分だけ卓を大きく（330〜520px）。
- ヘッダーの画面名と節の見出しのハザードティックをやめた。

### 3.7 卓とカードを大きく（さつきの指示。2026-09-29）

- カードが小さすぎる → ボードの札を前の 2.5 倍（スマホの回答で 24px → 60px 前後）。卓の幅に合わせて決める（5 枚と間で卓の幅の 86%、最大 64px。360px 幅の端末では 52px 前後）。
  ホールカードは 2.5 倍にすると席が卓を覆うので、ボードの札の 0.58 倍（前の 1.5 倍ほど。2 枚で席のプレートの幅）。
- 横の席が卓を細長くしていた → 卓（フェルト）を幅いっぱい（左右 6%）に広げ、横の席は縁に重ねる。横の席は上下（27% / 73%）に寄せ、卓の中央をボードに空ける。
  チップは横の席なら同じ高さの内側、上下の席なら中央寄り（ボードに重ならない所）。4 人は下・左上・上・右上。
- ホールカードは席のプレートの上に浮かせる（カードの有無で席が動かない。上の席はプレートの右）。ポットはボードの上、終わりの表示はボードの下に添える。
- 隙間を無くす → 投稿のアクションのステップ、回答のリプレイのタブ、集計の Hand History のタブ（スマホ）は、画面の高さちょうどにして卓で残りを埋める。
  下の余白は下に固定したバー（アクションの台・戻る / 次へ・Range 入力）の実際の高さ。アクションの台は局面で高さが変わるので、いちばん高かった値を保つ（そのたびに卓が伸び縮みしないように）。
- 投稿者が自分の投稿に回答するときも、リプレイの Hero のハンドは伏せる（回答してから集計で見せる。06 章 §4.3）。

### 3.2 回答（レンジ入力）

- スマホのレンジタブの上に**スポットの要約**の 1 行（ボードの札・「BTN Hero ベット 6.5」・POT）。押すとリプレイのタブへ。
- 下部のバー（PC はレンジ表の下）を「**{n} combos · {x}%**」とレンジの中のアクションの割合に変えた（前は 1326 combos に対する各キーとレンジ外の比率）。
  レンジが空なら「0 combos · 0.0%」、割合はすべて 0.0%。

### 3.3 集計

- 集計の先頭に**答え合わせ**（Villain の実際のアクションとハンド）を置いた（前はレンジ表の下）。
- 上部のバーを「全体」「自分」の 2 本に（各々 combos・% とレンジの中の割合）。「自分」のタブでは自分の 1 本だけ。
- タブに「**自分との差**」を足した（回答が 1 件以上で自分の回答があるとき）。マスの差 = キー（fold / check / call / s1）とレンジ外の割合の、
  自分と全体の差の絶対値の和の半分（0〜100%）。表は差の大きさを黄の濃さ（0.15 + 0.85 × 差）で塗る。差 0 のマスは塗らない。
  内訳に「差 {n}%」。全体の割合は回答者全員に対する割合（レンジに入れなかった人をレンジ外として数える）。
- マスの内訳に「全体」「自分」の細いバーを足した（空きはレンジに入れなかった割合）。
- **次のスポット**: 新着順の一覧から、未回答・自分の投稿でない・今の投稿でない最初のスポット（最大 3 ページ＝60 件まで探す）。
  あればスマホは下部に固定、PC は集計の最後にボタン。無ければ出さない。

### 3.4 スポット一覧

- カード全体を押せる（タイトルのリンクをカードいっぱいに広げる）。右下の「回答する ›」（黄）・「結果を見る ›」（シアン）は目印（読み上げはタイトル）。
- 回答済みのカードはタイトルを少し沈める。区切り線をやめ、余白を詰めた。削除のボタンは今までどおり（カードの上に重ねる）。

## 4. 採らなかったもの

| 型 | 理由 |
|---|---|
| 略記の文字入力（H-10） | 上級者向けで慣れが要る（フォーラムの声）。台とキーボードで足りている。必要ならさつきと相談 |
| 上位 X% で塗る・塗っていないマスをまとめて塗る（R-6） | プリフロップの強さの順は、フロップ以降のスポットのレンジには当てはまらない。空きを一括で塗ると「レンジ外」の意味が崩れる |
| 正解・不正解の採点・スコア・連続記録 | ソルバーの正解を持たない集合知の道具なので、採点はしない（CLAUDE.md の「やらないこと」） |
| 一覧の「未回答」の絞り込み（L-2） | `list_posts` の変更（マイグレーション）が要る。次のスポットのボタンで代わりになるか様子を見る |
| 一覧のカードにボード | 同じく `list_posts` の変更が要る。要望があれば別の作業で |
| 席を押してその席まで Fold to | 卓の席を押すとハンドの編集と取り違えやすい。台の Fold to の行で足りる |
