# 06 画面仕様

仕様書 §4・§5 を、画面ごとの状態・入力・バリデーション・エラー表示・空状態まで具体化したもの。
見た目は `.claude/skills/wwyd-ui-concept`（ICMCLEC 踏襲）に従う。モックからは画面構成と操作だけを採る。

**全画面に共通の制約**: 画面上に説明文を出さない（ⓘ に集約。例外はプレースホルダーとエラー表示）。
操作方法を説明するトーストを出さない。表示する文言は、この章に書いたラベル・データ・エラー文だけとする。

## 0. 共通

### 0.1 ルーティング

| パス | 画面 | 備考 |
|---|---|---|
| `/` | スポット一覧 | クエリ `?tab=mine&street=flop&sort=many` で状態を保持 |
| `/new` | スポット投稿 | |
| `/s/:id` | 振り分け | `get_post_detail` の `viewer` で `answer` か `result` へ置き換え遷移 |
| `/s/:id/answer` | 回答（投稿者の自分の投稿への回答を含む） | 回答済みなら `/s/:id/result` へ |
| `/s/:id/result` | 集計 | 未回答の他人の投稿なら `/s/:id/answer` へ（サーバー側でも集計を返さない） |
| `/terms` | 利用規約 | 未ログインでも閲覧可（Google の同意画面にリンクするため） |
| `/privacy` | プライバシーポリシー | 同上 |
| その他 | 「ページが見つかりません」＋「一覧へ」 | |

- History API のルーティング（ハッシュではない。OAuth の戻り URL と衝突させないため）。静的ホスティング側で SPA のフォールバックを設定する（08 章）。
- 認証は PKCE フロー（supabase-js 既定）。

### 0.2 アプリの外枠

- **ヘッダー**（全画面・固定）: 左に「＜」（一覧へ。一覧以外。§0.2 の戻る導線）と画面名。画面名は一覧「スポット一覧」（ハザードティック付き）・投稿「スポット投稿」・回答「回答」・集計「結果」・規約「利用規約」「プライバシーポリシー」。本文に同じ見出しを重ねない（回答・集計は投稿のタイトル、規約は文書の題を本文に出す）。右に ⓘ ボタン、アカウントアイコン。アプリ名「WWYD」はログイン画面だけに出す（2026-09-29 さつき）。
- アカウントアイコンは汎用のアイコン（Google のプロフィール画像・名前・頭文字は出さない。不変条件 6）。
- **アカウントメニュー**: 「利用規約」「プライバシーポリシー」「ログアウト」「アカウントを削除」。
- **ⓘ**: 表示中の画面のインフォメーションモーダル（09 章）。
- 画面幅 **700px 未満はスマホ用 UI**（`matchMedia('(max-width: 699.98px)')`）。PC 版の縮小ではなく構成を変える。
- 戻る導線: ヘッダーの左の「＜」（一覧以外。読み上げの名前は「一覧へ」）。本文に「← 一覧へ」の行は置かない（2026-09-29）。
- 入力欄の見出しは欄の上に置く（横に置くと欄の左端が揃わない）。択一の切り替え（ゲーム形式・一覧のストリート・T4 のゲーム・集計の全体 / 自分）は横幅を等分したつながったボタン列（2026-09-29）。

### 0.3 アプリ全体の状態

| 状態 | 条件 | 表示 |
|---|---|---|
| 起動中 | セッション確認中 | ロゴのみ（文字なし） |
| 未ログイン | セッションなし | ログイン画面（§1） |
| 利用不可 | `whoami().allowed = false` | 「このアカウントは利用できません」＋「ログアウト」 |
| メンテナンス中 | Supabase に到達できない（ヘルスチェック失敗・5xx・タイムアウト 10 秒）（§8「停止中はメンテナンス中の静的表示」） | 「メンテナンス中」＋「再読み込み」 |
| オフライン | `navigator.onLine = false` かつ通信失敗 | 「オフラインです」＋「再読み込み」 |
| 通常 | 上記以外 | 各画面 |

### 0.4 共通部品の挙動

- **確認ダイアログ**: タイトル・本文・「やめる」「〈実行〉」。Esc と背景クリックで閉じる（= やめる）。破壊的な操作の実行ボタンは赤（`--red`）。
- **トースト**: エラーと、仕様書が明示したもの（スポイトの「レンジ外」）だけ。完了通知は出さない【Q-15】。2.2 秒で消える。`role="status"`（エラーは `role="alert"`）。
- **ボタンの処理中**: 通信中は押せなくし、ラベルを「…」付きにする（例「投稿中…」）。二重送信しない。
- **タッチ領域** 44px 以上（レンジ表のマスを除く）。キーボード操作・フォーカス表示（シアンのリング）。
- **視差効果を減らす設定**: アニメーションとリプレイの自動再生をしない（即座に停止位置を表示）。

## 1. ログイン画面【Q-13】

仕様書に画面の定義がないため、最小構成とする。

| 要素 | 内容 |
|---|---|
| アプリ名 | 「WWYD」（大きく） |
| サービスの説明 | 「ポーカーのスポットを投稿し、Villain のレンジを他のプレイヤーの回答から集合知として見るツール」（アプリ名の下に小さく 1 行。Google の OAuth 同意画面の「ホームページはアプリの機能を説明する」要件のため。不変条件 1 の例外。2026-09-28 さつきの決定） |
| ボタン | 「Google でログイン」（`signInWithOAuth({ provider: 'google' })`） |
| リンク | 「利用規約」「プライバシーポリシー」（下部に小さく） |
| ⓘ | ヘッダーの ⓘ でアプリの説明（09 章 §0） |

- エラー（同意を拒否した・失敗した）: 「ログインできませんでした」を表示。
- ログイン後は元のパス（なければ `/`）へ戻る。

## 2. スポット一覧（§5.1）

### 2.1 構成

| 要素 | PC | スマホ |
|---|---|---|
| 見出し | ヘッダーの画面名「スポット一覧」（§0.2） | 同じ |
| タブ | 「すべて」「自分の投稿」＋右に「＋ スポットを投稿」 | 「すべて」「自分の投稿」 |
| フィルタ | ストリート: 「すべて」「フロップ」「ターン」「リバー」（プリフロップは出題しない。04 章 §8.1。`?street=pf` は「すべて」）。4 等分のつながったボタン列。「ストリート」の文字は出さない（読み上げの名前だけ） | 同じ（横幅いっぱい） |
| 並び替え | 「新着順」「回答が多い順」。枠のない小さな文字の切り替え（選択中は黄）。ストリートと同じ行の右端 | ストリートの下の右寄せ |
| カード | グリッド（最小幅 300px） | 1 列 |
| 投稿ボタン | タブの右 | 画面下部に固定「＋ スポットを投稿」 |

### 2.2 カード

| 項目 | 表示 |
|---|---|
| ストリート | バッジ（フロップ / ターン / リバー。規則の変更前のプリフロップの投稿は「プリフロップ」） |
| ゲーム形式・実効スタック | 「キャッシュ · 100bb」「MTT · 22bb」 |
| 状態 | 「回答済み」または「自分の投稿」（右上） |
| タイトル | 最大 2 行（超えたら省略記号） |
| 席 | 「Hero BTN vs Villain BB」 |
| 回答数・経過時間 | 「37 人が回答 · 2時間前」 |
| 操作 | カード全体を押すと進む（2026-09-29。14 章 §3.4）。右下の目印: 未回答「回答する ›」（黄）、回答済み「結果を見る ›」（シアン）、自分の投稿で回答済み「回答を見る ›」。自分の投稿は「削除」（2026-09-28）。管理者: すべてのカードに「削除」。回答済みのカードはタイトルを沈める |

経過時間: 1 分未満「たった今」、60 分未満「n分前」、24 時間未満「n時間前」、1 日「昨日」、それ以降「n日前」。

### 2.3 状態

| 状態 | 表示 |
|---|---|
| 読み込み中（初回） | カードの骨組み 3 枚 |
| 追加読み込み | 最後のカードの下が見えたら次の 20 件を読む（IntersectionObserver）。読み込み中は小さなスピナー |
| 空（自分の投稿・ストリートすべて） | 「投稿なし」＋「スポットを投稿」ボタン |
| 空（それ以外） | 「該当スポットなし」 |
| エラー | 「読み込みに失敗しました」＋「再試行」 |

### 2.4 削除

確認ダイアログ: タイトル「この投稿を削除しますか」、本文「集まった回答もすべて削除されます。元には戻せません。」、「やめる」「削除する」。
成功したらカードを一覧から除く。失敗は「削除できませんでした」のトースト。

## 3. スポット投稿（§5.2）

### 3.1 構成

- **PC**: 上に「T4ハンドヒストリー画像を読み込む」。その下に 3 列（左:「基本設定」「プレイヤーとハンド」、中:「アクション入力」、右:「スポット」＋エラー一覧＋「投稿する」）。
- **スマホ**: 4 ステップ「基本設定 → プレイヤー → アクション → スポット」。上部にステップ表示（タップで移動可、完了済みはシアン）、下部に「戻る」「次へ：〈次のステップ名〉」、最終ステップは「投稿する」。エラー一覧は下部バーの中。節の見出し（「基本設定」など）はステップ表示と同じなので画面に出さない（読み上げにだけ残す）。アクションのボタンは 1 行目「フォールド」「チェック」「コール」、2 行目「ベット」「レイズ」。スポットの候補には欄の見出し「Hero のアクション」（2026-09-29）。

### 3.2 下書きの保持

入力中の下書きはメモリに保持する（一覧に戻っても消えない。再読み込みで消える）。投稿成功または「すべて消す」で消える。
下書きがある状態でタブを閉じる・再読み込みするときはブラウザの離脱確認を出す（`beforeunload`）。

### 3.3 基本設定

| 項目 | 入力 | 既定値 | バリデーション |
|---|---|---|---|
| ゲーム形式 | 切り替え「キャッシュ」「MTT」 | キャッシュ | — |
| SB（bb） | 数値 | 0.5 | 0 < SB ≤ BB、小数第 3 位まで |
| BB（bb） | 表示のみ「1」【Q-4】 | 1 | — |
| アンティ（bb） | 数値（空は 0） | 0 | ≥ 0、小数第 3 位まで |
| レーキ（%） | 数値（キャッシュのみ。MTT では非活性で空） | 空 | 0〜100、小数第 2 位まで。保存するが計算に使わない |

- アクションを 1 つでも入力すると、基本設定・スタック・Hero の席は非活性（ロック）。解除は「すべて消す」。

### 3.4 プレイヤーとハンド

最初に「人数」（2〜6 の等分のボタン列）を選ぶ（**必須**。選ぶまで席の表は出さない。2026-09-29 さつき）。席は早い席から空く
（04 章 §2.1）。空席になった席のハンドは消し、Hero が空席になったら BTN にする。T4 の画像を読み込むと 6 人。アクションを入れると人数もロック。
未選択のまま進むと、アクションの節は「プレイヤーの人数を選択してください」、投稿時も同じ文言のエラー。

座っている各席の行: 「席」「スタック（bb）」「ハンド（2 枠）」「Hero（ラジオ）」。

| 項目 | 既定値 | バリデーション |
|---|---|---|
| 人数 | なし | 2〜6 のどれか（必須） |
| スタック | 100 | 0 < スタック ≤ 9999.999、小数第 3 位まで |
| Hero | BTN | 座っている 1 席必須 |
| ハンド | 空 | 0 枚か 2 枚（1 枚・スート未確定はエラー）。Hero は 2 枚必須 |

- ハンド欄を押すとカードキーボード（§3.5）が画面下部に出る。押した欄がキーボードに隠れないよう自動スクロール。
- 入力中の欄はシアンの枠。ランクだけ入った枠は「K?」のように表示。

### 3.5 カードキーボード（§5.2.5）

```
7  8  9  [Q]
4  5  6  [Q]
A  2  3  [♠]
[C ][ ⌫ ] [♠]
```

（2026-09-29 さつきの指示で変更: A は単独のキー（元の 1 の位置）、1 と 0 のキーは廃止、C と ⌫ が下の段を等分。
フリックのキーは右端の列なので、右（画面の外側）には割り当てず左へ払う。キーの面に払う先の文字を小さく出す。
スートのキーも絵札のキーと同じ形（中央は濃く、周りは薄く。札の面や色は付けずシルエットだけ）。キーの 1 段の高さは画面の高さの 7.5%（48〜68px）で、キーボードの上端が画面のおよそ 6 割の位置に来る。）

| 入力 | 動作 |
|---|---|
| 2〜9・A | ランク |
| Q（タップ / 上 / 左 / 下） | Q / K / T / J |
| ♠（タップ / 上 / 左 / 下） | ♠ / ♥ / ♦ / ♣ |
| パソコンのキーの 1 → 0 | T（1 → 0 以外のランクはそのランクに置き換え、1 → スートは無視、0 単独は無視） |
| スート待ちでランク | 直前のランクを置き換え |
| ランク待ちでスート | 無視 |
| 3 枚目 | 無視 |
| C | その席のハンドを消す |
| ⌫ | 1 文字消す |
| 使用済みのカード | 入力せず、エラートースト「{カード} は使用済み」 |

- フリック: 押して 150ms 経過、またはドラッグ開始（5px 超）でポップアップ。方向は移動距離 25px 超で判定（上 -135°〜-45°、右 -45°〜45°、下 45°〜135°、左それ以外）。ポップアップは左と中央の 2 列（中央の列をキーの中央に合わせる）で、キーボード領域からはみ出さないよう補正。
- 閉じる: 「完了」、キーボード外のタップ、Esc。
- ヘッダー行: 入力中の席名（例「BTN」）、「←」「→」（前の席・次の席。座っている席を巡る。UTG の前は BB、BB の次は UTG。2026-09-29）、「完了」。
- スート色は 4 色デッキ（♠ 白〜グレー、♥ 赤、♦ 青、♣ 緑。ICMCLEC の札色）。

### 3.6 アクション入力（§5.2.6）

手番の操作は**アクションの台**にまとめる（2026-09-29 に作り直し。考え方と試験の記録は 13 章）。PC は節の中（卓の下）、
スマホは画面の下に固定（親指の届く所。ハンドを入れている間は「戻る」「次へ」の代わりに出す）。
節の上には入力中のハンドの**卓**を出す（回答画面と同じ部品。Hero を手前、手番の席を黄のグロー、スタック・直前のアクション・ベットのチップ・ポット・ボード。14 章 §3.1）。
台は上から:

- **手番の見出し**: 席（ポジションの色）・ストリート・「POT {ポット（このストリートのベットを含む）}」・「残り {スタック}」、右端に「1つ戻す」（アイコン）。
- **よく使う額**（ベット / レイズが合法なときだけ。横にスクロール）。押すと額を選ぶだけ（打つのは下のボタン）:
  - プリフロップのオープン: 2 / 2.2 / 2.5 / 3bb（リンプがあれば 3 / 4 / 5bb＋リンプ 1 人につき 1bb）
  - プリフロップの 3bet 以降: 直前のレイズ（to）の ×2.2 / ×2.5 / ×3 / ×4
  - フロップ以降のベット: ポットの 25 / 33 / 50 / 75 / 100 / 150%（0.1bb に丸める）
  - フロップ以降のレイズ: 直前のベット（to）の ×2.5 / ×3 / ×4
  - 最後に「オールイン」。最小に満たない額・オールイン以上の額は出さない。倍率と % には額（bb）を小さく添える
  - 最初に選んでおく額: オープン 2.5・3bet ×3・ベット 33%・レイズ ×3（無ければ最小）
- **Fold to / Check to**: ベットがあればフォールド、なければチェックを続けて、そのストリートのうちに手番が回る席のボタン（2 手以上の分だけ）。
  押すと途中の席のフォールド（チェック）をまとめて入れる。右に額の入力欄（「to」または「bet」。自由な額）。
- **3 つのボタン**（位置は手番ごとに動かない）: 「フォールド」／「チェック」または「コール {額}」／「ベット {額}」または「レイズ {額}」。
  ボタンの名前は局面に合わせる（14 章 §3.1）: プリフロップ「オープン」（リンプがいれば「レイズ」）→「3bet」→「4bet」…、レイズの無いプリフロップの BB 以外のコールは「リンプ」、フロップ以降「ベット」→「レイズ」→「3bet」…。
  取れないものは非活性（04 章 §5）。コール・ベット・レイズがオールインになるときは「オールイン」を添える。
  - 範囲外・小数第 4 位以上の額で押す → 入力せず、エラートースト「{min}〜{max}bb」。
- ボードを待つ間の台: 「{ストリート}のカード」と「{ストリート}のカードを選ぶ」（ピッカーを閉じたとき開き直す）。
- **ボード**: 卓の中の 5 枠。ストリートが終わる（`streetEnd` / `runout`）と次の枠の「＋」が押せるようになり、カードピッカー（13×4、使用済みは非活性）が自動で開く。枚数が揃うまで続けて開く。
- 入力済みのボードカードを押す → そのカード以降のボードと、そのストリート以降のアクションを消す（確認なし）。
- 「1つ戻す」: 最後のアクションだけ取り消す。ボードは残す（再到達時にボード入力を求めない）。まだ来ていないストリートのカードは薄く出す。
- 「すべて消す」: アクションとボードを消す（ロック解除）。
- **ログ**: 回答画面のハンドヒストリーと同じ形（ストリートごとの列、席の色、最新のアクションを強調、スポットに選んだ手に「出題」）。
  1 手を押す → 確認ダイアログ「{手} から入れ直しますか」（本文「この手から後のアクションを消します。」、「やめる」「入れ直す」）→ その手から後のアクションを消す（ボードは残す）。
- **終了表示**: 卓の中央に「{席} ポット獲得」または「ショーダウン」。ベットはポットに回収して出す。ショーダウンでは残った各席の入力済みハンドを卓に出し、未入力は「マック」。
- 投稿時に、到達したストリートより後のボードカードは送らない（「1つ戻す」で残ったカード）。

### 3.7 スポット（§5.2.7）

- **Hero のアクションの候補**: Hero の**フロップ以降**のアクションだけ（04 章 §8.1。2026-09-28 さつき）。ラジオの一覧。各行「{ストリート}」「{Hero の席} {アクション}」（例「ターン / BTN ベット 6.5」）。候補なしなら「候補なし」。
- 候補が 1 つでも自動では選ばない（どのアクションで募集するかは投稿者が明示的に選ぶ）。
- **Villain**: カスタムのセレクト（ネイティブ `<select>` は使わない）。候補が 1 席なら自動選択・非活性。
- **タイトル**: プレースホルダー「タイトル（40文字まで）」、文字数「n / 40」（コードポイント数で数える）。
- アクションを変えて選んでいた候補が消えたら、スポットと Villain の選択を解除する。

### 3.8 投稿時のバリデーション（§5.2.8）と表示

「投稿する」を押したとき、クライアントで次を検査し、失敗を**一覧**で表示する（PC は右列、スマホは下部バー）。

| 条件 | エラー文 |
|---|---|
| Hero のハンドが 2 枚でない | 「Hero（{席}）のハンドを入力してください」 |
| 途中のハンドがある | 「{席} のハンドが途中です」 |
| ハンドが最後まで入力されていない | 「ハンドを最後まで入力してください」 |
| 設定値が不正 | 「{項目} の値が正しくありません」 |
| スポット未選択 | 「スポットを選択してください」 |
| Villain 未選択 | 「Villain を選択してください」 |
| タイトルが空 | 「タイトルを入力してください」 |

問題がなければ Edge Function `create-post` に送る（ボタン「投稿中…」）。成功 → 一覧の「自分の投稿」タブへ（下書きを消す）。
失敗 → エラーコード表（§7）の文を一覧に表示。

### 3.9 画像読み込み（§5.2.2、07 章）

- 置き場所: PC は 3 列の上、スマホは 1 ステップ目（基本設定）の上（モックと同じ）。T4 の画面からダウンロードした画像だけを読む（07 章 §0）。
- 「T4ハンドヒストリー画像を読み込む」→ ダイアログ「T4 のゲーム」で **通常 / エキスパート** を選ぶ（各ボタンに「レーキ 5%（4bb cap）」「レーキ 5%（0.6bb cap）」。入力中の内容があれば「入力中の内容は画像の内容に置き換わります。」も出す）→ ファイル選択（PNG / JPEG / WebP）。
  選んだゲームで基本設定を入れる: キャッシュ・SB 0.5 / BB 1・アンティ 0・レーキ 5%（2026-09-28 さつきの指示。T4 はアンティなし。レーキの cap は保存しない。§07 §3）。
- 処理中: 全面に「読み取り中…」とキャンセル（スマホは下からのシート）。キャンセルすると入力は変わらない。
- **投稿できないハンドは読み込みの時点ではじく**（2026-09-28 さつき）。確認画面を開かず、ボタンの下にエラー表示。フォームは変えない。判定は画像で読んだ席・ストリート・ボードのまま（再生しない。`ocrPostability`）。
  - フロップが開いていない、または Hero のフロップ以降のアクションに出題できるもの（§3.7）が無い: 「フロップ以降の Hero のアクションがないハンドです」。
  - フロップ以降のアクションがあるのにフロップが読めない（スクリーンショットなど）: 「読み取れませんでした」（その画像はあきらめてもらう）。
  - Hero の席やどこかの行の席が読めないときは、はじかずに確認画面で直してもらう。
- 成功: **確認画面「読み取り結果」**を全面に出す（2026-09-28 さつきの指示。OCR は 100% とは限らないため）。
  - PC は左に画像・右に結果、スマホはタブ「結果 / 画像」。上部に「やめる」「反映する」。画像はメモリから表示するだけで、閉じたら破棄する。
  - 直せるもの: T4 のゲーム（チップ）、各席のハンド（押すとカードキーボード）と Hero（各席の「HERO」）、ボード（押すとカードピッカー。× で最後の 1 枚を消す）、
    アクション（行ごとに動詞のセレクトと額（ベット・レイズ・オールイン）、「＋」で下に行を足す、「×」で消す、「アクションを足す」）。
  - アクションの席とストリートは先頭から再生して決まる（表示だけ。ストリートが変わる所に見出し）。画像で読んだ席と合わない行、再生できない行は赤。
  - 下に問題の一覧（エラー表示）: 「{席} のハンドがありません」「{席} のハンドが正しくありません」「ボードが正しくありません」「{n}手目から席が画像の読み取りと合いません」「{n}手目のアクションが正しくありません」「{n}手目以降のアクションが足りません」。ほかに問題が無く最後まで再生できたのに出題できるアクションが無ければ（Hero の直し間違いなど）「フロップ以降の Hero のアクションがないハンドです」。
  - 「反映する」: 確認画面の内容をフォームに反映（上書き。問題があっても再生できたところまで）。スポットと Villain の選択は解除。スタック・タイトルは利用者の入力のまま。「やめる」・Esc: フォームは変えない。
  - 読み込み・確認の途中で画面の幅が変わって PC / スマホのレイアウトが切り替わっても、状態を保つ。
- 失敗: 「読み取れませんでした」（エラー表示。フォームは変えない）。
- 画像はメモリ上で処理し、終わったら参照を捨てる（保存・送信しない）。

## 4. 回答（レンジ入力）（§5.3）

### 4.1 構成

- 上部: メタ行「{ストリート} · {形式} · {実効}bb · SB {sb} / BB 1 · アンティ {ante}」、タイトル。
- **PC**: 左にリプレイ、右にレンジ入力（ブラシパネル → レンジ表 → サイズ → 集計バー → エラー → 送信）。
- **スマホ**: 上部固定のタブ「リプレイ / レンジ」。
  - リプレイタブ: テーブル、再生コントロール、ハンドヒストリー（折りたたみ）。下部に「レンジ入力」。
  - レンジタブ: 上部固定パネルに「スポットの要約」（ボード・出題の Hero のアクション・POT の 1 行。押すとリプレイのタブへ。14 章 §3.2）、「ブラシパネル」と「サイズ（畳んだ 1 行）」、その下にレンジ表。下部に集計バーと「回答する」を固定。**レンジ表の下に操作要素を置かない**。

### 4.2 データの読み込みと振り分け

`get_post_detail(id)` を呼ぶ。

| 結果 | 動作 |
|---|---|
| 回答済み（`viewer = answered`、または投稿者で `my_answer` あり） | `/s/:id/result` へ置き換え遷移 |
| 未回答（`viewer = unanswered`、または投稿者で `my_answer` なし） | 回答モード（送信ボタン「回答する」）。投稿者も他の回答者と同じ（2026-09-28。Hero の想定レンジは廃止） |
| `post_not_found` | 「スポットが見つかりません」＋「一覧へ」 |
| その他のエラー | 「読み込みに失敗しました」＋「再試行」 |

### 4.3 リプレイ（§5.3.2）

- 開くと停止位置まで自動再生（1 手 650ms）。視差効果を減らす設定では即座に停止位置。
- 操作: 「最初から」「1手戻る」「再生 / 一時停止」「1手進む」（停止位置より先へは進めない）。進捗「{n} / {停止位置} 手目」。
- テーブル: Villain の席を手前（下中央）に回転。ラベル: Hero の席「Hero」、Villain の席「Villain（あなた）」（シアンの枠で強調）。to act の席は黄のグロー。
- Hero のハンドは裏向き。投稿者が自分の投稿に回答するときは、自分のハンドなので表向き【Q-14】。席の表示はどちらも「Villain（あなた）」。
- 表示: ポット、ボード（到達ストリート分）、各席のスタック・直前のアクション・ベット額のチップ。
- ログ: 停止位置まで。出題の Hero のアクションに「出題」タグ。停止時は「▶ {Villain} to act」。

### 4.4 ブラシとミックス（§5.3.3）

- **タイル**: 合法キーごと（`fold, call, s1` / `fold, call` / `check, s1` / `check`）。表示: アクション名、頻度（%）、コール額または「レイズ（ベット）サイズ」。押すとそのキー 100% のブラシ。
- **ミックスバー**: キーの順に区間を並べ、境界にハンドル。ドラッグで隣接キーの頻度を 5% 刻みで調整。ハンドルは `role="slider"`、左右キーで ±5%。
- **重なったハンドル**: ドラッグ開始時に移動 6px 未満の間は掴むハンドルを決めない。その方向へ**動けるハンドル**を掴む（仕様書 §5.3.3）。右へ動いたら重なりのうち最も右のハンドル（間の区間の右端）、左へ動いたら最も左のハンドルを掴む。ほかのハンドルは 0% の区間を挟んで隣に止められ、その向きには動けない【Q-30】。
- 初期ブラシ: `call` があれば call 100%、なければ先頭キー 100%。
- ブラシの合計は常に 100%。

### 4.5 塗り（§5.3.4）

- マスをタップ、またはなぞるとブラシのミックスで塗る。なぞった一連の操作で 1 手（元に戻す単位）。
- ブラシと同じミックスのマスから始めた場合は消去として動作（なぞった範囲も消去）。
- マス表示: 左から fold → check → call → s1 の順に頻度の幅で色を並べる。レンジ外は `--cell-off`。
- **スポイト**: 480ms 長押し（移動 6px 未満）で、その操作による塗りを取り消し、そのマスのミックスをブラシに読み込む（トーストなし）。レンジ外のマスでは「レンジ外」とトースト。
- レンジ表は `touch-action: none`、選択不可。

### 4.6 道具（§5.3.5）

「ブラシ / 消しゴム」の切り替え、「元に戻す」「やり直す」（最大 100 手）、「クリア」（元に戻す対象）。
取れないアクション（例: fold / call が合法な局面の「チェック」「ベット」）は PC では非活性ボタンとして並べ、スマホでは出さない。

### 4.7 サイズ（§5.3.6）

- s1 が合法なときだけ。畳んだ 1 行「レイズサイズ 17.55bb 50% pot」（ベットなら「ベットサイズ」、max なら「オールイン」）。
- 開くと: プリセット「33%」「50%」「75%」「125%」「オールイン」、入力欄（bb、0.1 刻みの増減、直接入力は小数第 3 位まで）、ゲージ（min〜max）、「min {min} / max {max}bb」、範囲外なら「範囲外」（赤）。
- 初期値 50%（04 章 §9）。

### 4.8 集計バー（§5.3.7）

レンジの大きさ「{n} combos · {x}%」（1326 combos に対する比率。combos は小数第 1 位まで）と、レンジの中の各キーの割合を積み上げバーと数値（小数第 1 位）で常時表示（2026-09-29。14 章 §3.2。前は 1326 combos に対する各キーとレンジ外の比率）。計算の元は 05 章 §4.2。

### 4.9 送信（§5.3.8）

| 検査（クライアント） | エラー文（`role="alert"`） |
|---|---|
| 1 マスも塗っていない | 「1マス以上塗ってください」 |
| s1 を含むマスがあり、サイズが範囲外 | 「サイズを {min}〜{max}bb にしてください」 |

- 回答モード: 確認ダイアログ タイトル「回答を送信しますか」、本文「送信後は変更できません。」、「やめる」「送信する」。
  送信 = `answers` への insert。成功 → `/s/:id/result`。`already_answered` → `/s/:id/result`（エラー表示なし）。
- 投稿者の回答も同じ（確認ダイアログ → `answers` への insert → 集計へ）。
- 送信前に画面を離れる場合、塗りがあればブラウザの離脱確認を出す。

## 5. 集計（§5.4）

### 5.1 構成

未回答（投稿者も含む）なら `/s/:id/answer` へ置き換え遷移。投稿者も回答するまで自分の投稿の集計を見られない（2026-09-28）。

### 5.2 集計レンジ（§5.4.2）

- タブ: 他人の投稿も自分の投稿も「全体（N人）」「自分」、回答が 1 件以上で自分の回答があれば「自分との差」（14 章 §3.3。差の大きさを黄の濃さで塗り、内訳に「差 {n}%」）。
- 全体表示・自分の表示の計算は 05 章 §4。
- 白枠: Villain の実際のハンド（known_cards がカードのときだけ）。
- マスを選ぶと内訳: 全体 = 「{ラベル}」「レンジ内 {n} / {N}人」、全体・自分の細いバー（14 章）、キーごとに「{名前} {平均%}（{人数}人）」、「自分：{自分のミックス or レンジ外}」。自分 = 「{ラベル}」と「{名前} {%} / …」または「レンジ外」。
- 初期選択マス: Villain の実際のハンドがあればそのマス、なければ AA。
- 上部: 「全体」「自分」のまとめ（§4.8 と同じ形。「自分」のタブでは自分だけ）。全体は 05 章 §4.1 の比率から出す。
- 空状態: 全体で回答 0 件 → 「回答なし」。

### 5.3 実際のアクション（§5.4.3）

「Villain（{席}）実際のアクション」＋「コール」「レイズ 12bb」など。ハンド: カード表示＋ラベル、または「マック」「ハンド不明」。

### 5.4 ハンドヒストリー（§5.4.4）

- ログ: Hero のスポットのアクションに「出題」タグ、Villain の実際のアクションを強調（黄）。
- テーブルの向きは回答画面と同じ（Villain を手前）。

### 5.5 操作（§5.4.5）
