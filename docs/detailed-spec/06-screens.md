# 06 画面仕様

仕様書 §4・§5 を、画面ごとの状態・入力・バリデーション・エラー表示・空状態まで具体化したもの。
見た目は `.claude/skills/wwyd-ui-concept`（ICMCLEC 踏襲）に従う。モックからは画面構成と操作だけを採る。

**全画面に共通の制約**: 画面上に説明文を出さない（ⓘ に集約。例外はプレースホルダーとエラー表示）。
操作方法を説明するトーストを出さない。表示する文言は、この章に書いたラベル・データ・エラー文だけとする。

---

## 0. 共通

### 0.1 ルーティング

| パス | 画面 | 備考 |
|---|---|---|
| `/` | スポット一覧 | クエリ `?tab=mine&street=flop&sort=many` で状態を保持 |
| `/new` | スポット投稿 | |
| `/s/:id` | 振り分け | `get_post_detail` の `viewer` で `answer` か `result` へ置き換え遷移 |
| `/s/:id/answer` | 回答（Hero の想定レンジの入力を含む） | 回答済みの他人の投稿なら `/s/:id/result` へ |
| `/s/:id/result` | 集計 | 未回答の他人の投稿なら `/s/:id/answer` へ（サーバー側でも集計を返さない） |
| `/terms` | 利用規約 | 未ログインでも閲覧可（Google の同意画面にリンクするため） |
| `/privacy` | プライバシーポリシー | 同上 |
| その他 | 「ページが見つかりません」＋「一覧へ」 | |

- History API のルーティング（ハッシュではない。OAuth の戻り URL と衝突させないため）。静的ホスティング側で SPA のフォールバックを設定する（08 章）。
- 認証は PKCE フロー（supabase-js 既定）。

### 0.2 アプリの外枠

- **ヘッダー**（全画面・固定）: 左にアプリ名「WWYD」（一覧へのリンク）。右に ⓘ ボタン、アカウントアイコン。
- アカウントアイコンは汎用のアイコン（Google のプロフィール画像・名前・頭文字は出さない。不変条件 6）。
- **アカウントメニュー**: 「利用規約」「プライバシーポリシー」「ログアウト」「アカウントを削除」。
- **ⓘ**: 表示中の画面のインフォメーションモーダル（09 章）。
- 画面幅 **700px 未満はスマホ用 UI**（`matchMedia('(max-width: 699.98px)')`）。PC 版の縮小ではなく構成を変える。
- 戻る導線: 各画面の左上に「← 一覧へ」（一覧以外）。

### 0.3 アプリ全体の状態

| 状態 | 条件 | 表示 |
|---|---|---|
| 起動中 | セッション確認中 | ロゴのみ（文字なし） |
| 未ログイン | セッションなし | ログイン画面（§1） |
| 利用不可 | `whoami().allowed = false` | 「このアカウントは利用できません」＋「ログアウト」 |
| メンテナンス中 | Supabase に到達できない（ヘルスチェック失敗・5xx・タイムアウト 10 秒）（§8「停止中はメンテナンス中の静的表示」） | 「メンテナンス中」＋「再読み込み」 |
| オフライン | `navigator.onLine = false` かつ通信失敗 | 「オフラインです」＋「再読み込み」 |
| 通常 | 上記以外 | 各画面 |

### 0.4 共通部品の挙動

- **確認ダイアログ**: タイトル・本文・「やめる」「〈実行〉」。Esc と背景クリックで閉じる（= やめる）。破壊的な操作の実行ボタンは赤（`--red`）。
- **トースト**: エラーと、仕様書が明示したもの（スポイトの「レンジ外」）だけ。完了通知は出さない【Q-15】。2.2 秒で消える。`role="status"`（エラーは `role="alert"`）。
- **ボタンの処理中**: 通信中は押せなくし、ラベルを「…」付きにする（例「投稿中…」）。二重送信しない。
- **タッチ領域** 44px 以上（レンジ表のマスを除く）。キーボード操作・フォーカス表示（シアンのリング）。
- **視差効果を減らす設定**: アニメーションとリプレイの自動再生をしない（即座に停止位置を表示）。

## 1. ログイン画面【Q-13】

仕様書に画面の定義がないため、最小構成とする。

| 要素 | 内容 |
|---|---|
| アプリ名 | 「WWYD」（大きく） |
| サービスの説明 | 「ポーカーのスポットを投稿し、Villain のレンジを他のプレイヤーの回答から集合知として見るツール」（アプリ名の下に小さく 1 行。Google の OAuth 同意画面の「ホームページはアプリの機能を説明する」要件のため。不変条件 1 の例外。2026-09-28 さつきの決定） |
| ボタン | 「Google でログイン」（`signInWithOAuth({ provider: 'google' })`） |
| リンク | 「利用規約」「プライバシーポリシー」（下部に小さく） |
| ⓘ | ヘッダーの ⓘ でアプリの説明（09 章 §0） |

- エラー（同意を拒否した・失敗した）: 「ログインできませんでした」を表示。
- ログイン後は元のパス（なければ `/`）へ戻る。

### 2.2 カード

### 2.3 状態

### 2.4 削除

確認ダイアログ: タイトル「この投稿を削除しますか」、本文「集まった回答もすべて削除されます。元には戻せません。」、「やめる」「削除する」。
成功したらカードを一覧から除く。失敗は「削除できませんでした」のトースト。

## 3. スポット投稿（§5.2）

### 3.1 構成

- **PC**: 上に「T4ハンドヒストリー画像を読み込む」。その下に 3 列（左:「基本設定」「プレイヤーとハンド」、中:「アクション入力」、右:「スポット」＋エラー一覧＋「投稿する」）。
- **スマホ**: 4 ステップ「基本設定 → プレイヤー → アクション → スポット」。上部にステップ表示（タップで移動可、完了済みはシアン）、下部に「戻る」「次へ：〈次のステップ名〉」、最終ステップは「投稿する」。エラー一覧は下部バーの中。

### 3.2 下書きの保持

入力中の下書きはメモリに保持する（一覧に戻っても消えない。再読み込みで消える）。投稿成功または「すべて消す」で消える。
下書きがある状態でタブを閉じる・再読み込みするときはブラウザの離脱確認を出す（`beforeunload`）。

### 3.3 基本設定

| 項目 | 入力 | 既定値 | バリデーション |
|---|---|---|---|
| ゲーム形式 | 切り替え「キャッシュ」「MTT」 | キャッシュ | — |
| SB（bb） | 数値 | 0.5 | 0 < SB ≤ BB、小数第 3 位まで |
| BB（bb） | 表示のみ「1」【Q-4】 | 1 | — |
| アンティ（bb） | 数値（空は 0） | 0 | ≥ 0、小数第 3 位まで |
| レーキ（%） | 数値（キャッシュのみ。MTT では非活性で空） | 空 | 0〜100、小数第 2 位まで。保存するが計算に使わない |

- アクションを 1 つでも入力すると、基本設定・スタック・Hero の席は非活性（ロック）。解除は「すべて消す」。

### 3.4 プレイヤーとハンド

各席（UTG, HJ, CO, BTN, SB, BB）の行: 「席」「スタック（bb）」「ハンド（2 枠）」「Hero（ラジオ）」。

| 項目 | 既定値 | バリデーション |
|---|---|---|
| スタック | 100 | 0 < スタック ≤ 9999.999、小数第 3 位まで |
| Hero | BTN | 1 席必須 |
| ハンド | 空 | 0 枚か 2 枚（1 枚・スート未確定はエラー）。Hero は 2 枚必須 |

- ハンド欄を押すとカードキーボード（§3.5）が画面下部に出る。押した欄がキーボードに隠れないよう自動スクロール。
- 入力中の欄はシアンの枠。ランクだけ入った枠は「K?」のように表示。

### 3.5 カードキーボード（§5.2.5）

```
7  8  9  [A]
4  5  6  [A]
1  2  3  [♠]
C  0  ⌫  [♠]
```

| 入力 | 動作 |
|---|---|
| 2〜9 | ランク |
| A（タップ / 上 / 右 / 下 / 左） | A / K / Q / J / T |
| ♠（タップ / 上 / 右 / 下） | ♠ / ♥ / ♦ / ♣ |
| 1 → 0 | T |
| 1 → 0 以外のランク | そのランクに置き換え |
| 1 → スート | 無視（確定しない） |
| 0 単独 | 無視 |
| スート待ちでランク | 直前のランクを置き換え |
| ランク待ちでスート | 無視 |
| 3 枚目 | 無視 |
| C | その席のハンドを消す |
| ⌫ | 1 文字消す |
| 使用済みのカード | 入力せず、エラートースト「{カード} は使用済み」 |

- フリック: 押して 150ms 経過、またはドラッグ開始（5px 超）でポップアップ。方向は移動距離 25px 超で判定（上 -135°〜-45°、右 -45°〜45°、下 45°〜135°、左それ以外）。ポップアップはキーボード領域からはみ出さないよう補正。
- 閉じる: 「完了」、キーボード外のタップ、Esc。
- ヘッダー行: 入力中の席名（例「BTN」）と「完了」。
- スート色は 4 色デッキ（♠ 白〜グレー、♥ 赤、♦ 青、♣ 緑。ICMCLEC の札色）。

### 3.6 アクション入力（§5.2.6）

- **状況行**: 「{席} to act · {ストリート} · to call {額} · スタック {額}bb」（to call は > 0 のときだけ）。
- **ボタン**: 「フォールド」「チェック」「コール {額}」「ベット」「レイズ」。合法でないものは非活性（04 章 §5）。
- **額の入力**（ベット / レイズが合法なときだけ）: ラベル「ベット」または「レイズ to」、数値入力、「{min}〜{max}bb」の範囲表示。
  - 初期値: to call = 0 → ポットの 50%（`pot + Σbets` の 50%、10mbb 単位に丸めて min〜max に収める）、to call > 0 → 最小レイズ to。
  - 範囲外・小数第 4 位以上で「ベット / レイズ」を押す → 入力せず、エラートースト「{min}〜{max}bb」。
- **ボード**: 5 枠。ストリートが終わる（`streetEnd` / `runout`）と次の枠の「＋」が押せるようになり、カードピッカー（13×4、使用済みは非活性）が自動で開く。枚数が揃うまで続けて開く。
- 入力済みのボードカードを押す → そのカード以降のボードと、そのストリート以降のアクションを消す（確認なし）。
- 「1つ戻す」: 最後のアクションだけ取り消す。ボードは残す（再到達時にボード入力を求めない）。
- 「すべて消す」: アクションとボードを消す（ロック解除）。
- **ログ**: ストリートごとの列（見出し = ストリート名＋そのストリートのボード）。最新のアクションを強調。
- **終了表示**: 「{席} ポット獲得」または「ショーダウン」。ショーダウンでは残った各席の入力済みハンドを並べ、未入力は「マック」。
- 投稿時に、到達したストリートより後のボードカードは送らない（「1つ戻す」で残ったカード）。

### 3.7 スポット（§5.2.7）

- **Hero のアクションの候補**: ラジオの一覧。各行「{ストリート}」「{Hero の席} {アクション}」（例「ターン / BTN ベット 6.5」）。候補なしなら「候補なし」。
- **Villain**: カスタムのセレクト（ネイティブ `<select>` は使わない）。候補が 1 席なら自動選択・非活性。
- **タイトル**: プレースホルダー「タイトル（40文字まで）」、文字数「n / 40」（コードポイント数で数える）。
- アクションを変えて選んでいた候補が消えたら、スポットと Villain の選択を解除する。

### 3.8 投稿時のバリデーション（§5.2.8）と表示

「投稿する」を押したとき、クライアントで次を検査し、失敗を**一覧**で表示する（PC は右列、スマホは下部バー）。

| 条件 | エラー文 |
|---|---|
| Hero のハンドが 2 枚でない | 「Hero（{席}）のハンドを入力してください」 |
| 途中のハンドがある | 「{席} のハンドが途中です」 |
| ハンドが最後まで入力されていない | 「ハンドを最後まで入力してください」 |
| 設定値が不正 | 「{項目} の値が正しくありません」 |
| スポット未選択 | 「スポットを選択してください」 |
| Villain 未選択 | 「Villain を選択してください」 |
| タイトルが空 | 「タイトルを入力してください」 |

問題がなければ Edge Function `create-post` に送る（ボタン「投稿中…」）。成功 → 一覧の「自分の投稿」タブへ（下書きを消す）。
失敗 → エラーコード表（§7）の文を一覧に表示。

### 3.9 画像読み込み（§5.2.2、07 章）

- 「T4ハンドヒストリー画像を読み込む」→ ファイル選択（PNG / JPEG / WebP）。
- 処理中: 全面に「読み取り中…」とキャンセル。
- 成功: 読み取れた項目をフォームに反映（既存の入力は上書き。先に確認ダイアログ「入力中の内容を置き換えますか」）。読めない項目（スタック・SB・アンティ等。07 章）は既定値のまま。
- 失敗: 「読み取れませんでした」（エラー表示）。
- 画像はメモリ上で処理し、終わったら参照を捨てる（保存・送信しない）。

## 4. 回答（レンジ入力）（§5.3）

### 4.1 構成

- 上部: 「← 一覧へ」、メタ行「{ストリート} · {形式} · {実効}bb · SB {sb} / BB 1 · アンティ {ante}」、タイトル。
- **PC**: 左にリプレイ、右にレンジ入力（ブラシパネル → レンジ表 → サイズ → 集計バー → エラー → 送信）。
- **スマホ**: 上部固定のタブ「リプレイ / レンジ」。
  - リプレイタブ: テーブル、再生コントロール、ハンドヒストリー（折りたたみ）。下部に「レンジ入力」。
  - レンジタブ: 上部固定パネルに「ブラシパネル」と「サイズ（畳んだ 1 行）」、その下にレンジ表。下部に集計バーと「回答する」を固定。**レンジ表の下に操作要素を置かない**。

### 4.2 データの読み込みと振り分け

`get_post_detail(id)` を呼ぶ。

| 結果 | 動作 |
|---|---|
| `viewer = answered` | `/s/:id/result` へ置き換え遷移 |
| `viewer = author` | Hero の想定レンジモード（送信ボタン「想定レンジを保存」、確認ダイアログなし、既存の想定レンジを読み込む） |
| `viewer = unanswered` | 回答モード（送信ボタン「回答する」） |
| `post_not_found` | 「スポットが見つかりません」＋「一覧へ」 |
| その他のエラー | 「読み込みに失敗しました」＋「再試行」 |

### 4.3 リプレイ（§5.3.2）

- 開くと停止位置まで自動再生（1 手 650ms）。視差効果を減らす設定では即座に停止位置。
- 操作: 「最初から」「1手戻る」「再生 / 一時停止」「1手進む」（停止位置より先へは進めない）。進捗「{n} / {停止位置} 手目」。
- テーブル: Villain の席を手前（下中央）に回転。ラベル: Hero の席「Hero」、Villain の席「Villain（あなた）」（シアンの枠で強調）。to act の席は黄のグロー。
- Hero のハンドは裏向き（回答モード）。Hero の想定レンジモードでは表向き【Q-14】。
- 表示: ポット、ボード（到達ストリート分）、各席のスタック・直前のアクション・ベット額のチップ。
- ログ: 停止位置まで。出題の Hero のアクションに「出題」タグ。停止時は「▶ {Villain} to act」。

### 4.4 ブラシとミックス（§5.3.3）

- **タイル**: 合法キーごと（`fold, call, s1` / `fold, call` / `check, s1` / `check`）。表示: アクション名、頻度（%）、コール額または「レイズ（ベット）サイズ」。押すとそのキー 100% のブラシ。
- **ミックスバー**: キーの順に区間を並べ、境界にハンドル。ドラッグで隣接キーの頻度を 5% 刻みで調整。ハンドルは `role="slider"`、左右キーで ±5%。
- **重なったハンドル**: ドラッグ開始時に移動 6px 未満の間は掴むハンドルを決めない。その方向へ**動けるハンドル**を掴む（仕様書 §5.3.3）。右へ動いたら重なりのうち最も右のハンドル（間の区間の右端）、左へ動いたら最も左のハンドルを掴む。ほかのハンドルは 0% の区間を挟んで隣に止められ、その向きには動けない【Q-30】。
- 初期ブラシ: `call` があれば call 100%、なければ先頭キー 100%。
- ブラシの合計は常に 100%。

### 4.5 塗り（§5.3.4）

- マスをタップ、またはなぞるとブラシのミックスで塗る。なぞった一連の操作で 1 手（元に戻す単位）。
- ブラシと同じミックスのマスから始めた場合は消去として動作（なぞった範囲も消去）。
- マス表示: 左から fold → check → call → s1 の順に頻度の幅で色を並べる。レンジ外は `--cell-off`。
- **スポイト**: 480ms 長押し（移動 6px 未満）で、その操作による塗りを取り消し、そのマスのミックスをブラシに読み込む（トーストなし）。レンジ外のマスでは「レンジ外」とトースト。
- レンジ表は `touch-action: none`、選択不可。

### 4.6 道具（§5.3.5）

「ブラシ / 消しゴム」の切り替え、「元に戻す」「やり直す」（最大 100 手）、「クリア」（元に戻す対象）。
取れないアクション（例: fold / call が合法な局面の「チェック」「ベット」）は PC では非活性ボタンとして並べ、スマホでは出さない。

### 4.7 サイズ（§5.3.6）

- s1 が合法なときだけ。畳んだ 1 行「レイズサイズ 17.55bb 50% pot」（ベットなら「ベットサイズ」、max なら「オールイン」）。
- 開くと: プリセット「33%」「50%」「75%」「125%」「オールイン」、入力欄（bb、0.1 刻みの増減、直接入力は小数第 3 位まで）、ゲージ（min〜max）、「min {min} / max {max}bb」、範囲外なら「範囲外」（赤）。
- 初期値 50%（04 章 §9）。Hero の想定レンジモードで既存の想定レンジがあればそのサイズ。

### 4.8 集計バー（§5.3.7）

1326 combos に対する各キーとレンジ外の比率を、積み上げバーと数値（小数第 1 位）で常時表示。計算は 05 章 §4.2。

### 4.9 送信（§5.3.8）

| 検査（クライアント） | エラー文（`role="alert"`） |
|---|---|
| 1 マスも塗っていない | 「1マス以上塗ってください」 |
| s1 を含むマスがあり、サイズが範囲外 | 「サイズを {min}〜{max}bb にしてください」 |

- 回答モード: 確認ダイアログ タイトル「回答を送信しますか」、本文「送信後は変更できません。」、「やめる」「送信する」。
  送信 = `answers` への insert。成功 → `/s/:id/result`。`already_answered` → `/s/:id/result`（エラー表示なし）。
- Hero の想定レンジモード: 確認なしで `save_host_answer`。成功 → `/s/:id/result`（集計タブ「Hero の想定レンジ」を選択した状態）。
- 送信前に画面を離れる場合、塗りがあればブラウザの離脱確認を出す。

## 5. 集計（§5.4）

### 5.1 構成

- **PC**: 左にハンドヒストリーの再生、右に集計。
- **スマホ**: 上部固定のタブ「集計 / ハンドヒストリー」。

`get_post_detail` の `viewer = unanswered` なら `/s/:id/answer` へ置き換え遷移。

### 5.2 集計レンジ（§5.4.2）

> 仕様書の「Hero の予想」は、画面・文書では「**Hero の想定レンジ**」と表示する（ボタンは「想定レンジを保存」「想定レンジを編集」「想定レンジを入力」、空状態は「想定レンジなし」。2026-09-28 さつきの決定）。


- タブ: 他人の投稿 = 「全体（N人）」「自分」「Hero の想定レンジ」。自分の投稿 = 「全体（N人）」「Hero の想定レンジ」。
- 全体表示・自分 / Hero の想定レンジの表示の計算は 05 章 §4。
- 白枠: Villain の実際のハンド（known_cards がカードのときだけ）。
- マスを選ぶと内訳: 全体 = 「{ラベル}」「レンジ内 {n} / {N}人」、キーごとに「{名前} {平均%}（{人数}人）」、他人の投稿では「自分：{自分のミックス or レンジ外}」。自分 / Hero の想定レンジ = 「{ラベル}」と「{名前} {%} / …」または「レンジ外」。
- 初期選択マス: Villain の実際のハンドがあればそのマス、なければ AA。
- 上部: 1326 combos 基準の積み上げバーと数値。
- 空状態: 全体で回答 0 件 → 「回答なし」。Hero の想定レンジなし → 「想定レンジなし」（自分の投稿では「想定レンジを入力」ボタン → `/s/:id/answer`）。

### 5.3 実際のアクション（§5.4.3）

「Villain（{席}）実際のアクション」＋「コール」「レイズ 12bb」など。ハンド: カード表示＋ラベル、または「マック」「ハンド不明」。

### 5.4 ハンドヒストリー（§5.4.4）

- 最初からハンドの最後まで再生できる（初期表示は最後の状態）。終了時は Hero のハンドと判明しているハンドを公開、「ショーダウン」または「{席} ポット獲得」。
- ログ: Hero のスポットのアクションに「出題」タグ、Villain の実際のアクションを強調（黄）。
- テーブルの向きは回答画面と同じ（Villain を手前）。

### 5.5 操作（§5.4.5）

- 削除は §2.4 と同じダイアログ。成功 → 一覧へ。
