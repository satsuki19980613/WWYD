## 0. 読む画像（2026-09-28 決定）

- 読む対象は **T4（tenfour-poker）の画面からダウンロードしたハンドヒストリー画像（PNG）だけ**とする。画面のスクリーンショットは対象外（さつきの指示）。
- **PC と Android でダウンロードした同じハンドの画像は、OCR で読む上で同じもの**と確かめた（サンプル `VIedHT`。2026-09-28）。
  - 大きさは両方とも幅 839px（流用元の正解画像と同じ）。カードの枠の位置・背景色は 1 ピクセル単位で一致。
  - 違いは端末のフォントで描かれる部分だけ: スートの記号（♠♥♦♣）の形、フッターの等幅の文字、文字のふち。スートは背景色で見分けるので影響しない。
  - 流用元の Python 版で両方を読むと、ポジション・カード 12 枚・収支・アクション 7 つと額・ハンド ID・日時がすべて一致。違ったのはプレイヤー名の読み違いだけ（名前は保存しない・席はバッジで結び付けるので影響しない）。
- iPhone でダウンロードした画像は未確認（保留）。手に入ったら同じ方法で比べる。

## 2. 流用元の手法と、ブラウザへの移植性

## 4. 本文認識の置き換え案（外部 API を使わず端末内で）

| 案 | 内容 | 長所 | 短所 | 工数（目安） |
|---|---|---|---|---|
| **(a) tesseract.js を自前ホスト** | WASM 版 Tesseract と `eng` の学習データを静的ファイルとして同じサイトから配信し、ボタンを押したときだけ読み込む | 流用元の処理（誤読辞書・正規表現）をほぼそのまま移せる。短期間 | 配信サイズが数 MB 増える（遅延読み込みで初回表示には影響させない）。1 枚数秒。誤読辞書の再調整が要る。**依存追加（要承認）** | 合計 **約 4〜6 人日**（6〜9 セッション） |
| (b) 固定フォント用の文字テンプレート OCR を自作 | T4 の固定フォントから英数字・記号のテンプレートを作り、ICMCLEC の照合部品で読む | 軽い・速い・依存なし | 文字分割とテンプレート作成の手間。名前（日本語・記号）は読めない前提で、席はバッジで決める必要 | 合計 **約 7〜11 人日** |

内訳（(a) の場合）: カード・スート・ボード・行検出の移植 1〜2 日、tesseract.js 組み込みと本文パーサの移植 1〜2 日、正解データでの検証と調整 1.5〜2 日。

**推奨: (a)**。理由: 精度実績のある流用元の処理をそのまま生かせ、工数が小さい。サーバー代は増えない（静的配信のみ）。
配信サイズは OCR ボタンを押したときだけ読み込むことで、通常の利用に影響させない。将来 (b) に差し替えられるよう、
OCR は `packages/ocr` の `readHandHistory(image: ImageData): Promise<OcrResult>` の 1 関数に閉じ込める。

## 5. プライバシーの担保

- 画像は `File` → `createImageBitmap` → Canvas → `ImageData` の順にメモリ上で処理し、終わったら参照を捨てる。IndexedDB・localStorage・サーバーのいずれにも保存しない。
- tesseract.js の WASM・学習データは**自サイトから**読み込む（CDN を使わない。初期設定の CDN 読み込みを必ず上書きする）。これで画像も含め外部通信が発生しない。
- プレイヤー名は、席の結び付けに一時的に使う場合もメモリ内に留め、`OcrResult` には含めない。テストで「結果に名前が含まれないこと」を検査する（流用元の `tests/test_no_personal_data.py` と同じ考え方）。
- CSP で `connect-src` を自サイトと Supabase に限定し、OCR 中の外部送信が起こらないことを構造的に保証する。

## 6. 正解データとテスト

- 流用元の `samples/` にある PNG と `*.expected.json` の組 22 件（6max のプリフロップ〜リバー、オールイン、3bet を含む）を、名前を除いた期待値に変換して `packages/ocr/fixtures/` に置く（**決定: 個人の対戦画像のため公開リポジトリには置かず、ローカルの `packages/ocr/fixtures-local/`（git 管理外）で検証する**。CI では画像を使わない単体テストのみ実行）【Q-17】。
- 合格基準（流用元に合わせる）: ボード 100%、プレイヤー・アクション 95% 以上。
- 画像の幅は 839px を前提にする（PC・Android のダウンロード画像は同じ。§0）。幅が違う画像は、幅で正規化してから読む（iPhone の確認までの保険）。

## 7. リスク

| リスク | 対策 |
|---|---|
| 画像の解像度・縮尺の違い | PC・Android は同じ（§0）。iPhone は未確認のため、幅で正規化してから座標を当てる |
| tesseract.js と Python 版で出力が違う | 誤読辞書を正解データで再調整 |
