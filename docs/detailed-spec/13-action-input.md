# 13. アクション入力の UX（2026-09-29）

投稿画面の「アクション」（ハンドヒストリーの入力）を、プロのポーカープレイヤーが意識しなくても素早く正しく
入力できるようにするための資料。さつきの指示（2026-09-29）で作成。**ルールの正は 04 章**（この章は入力する人の
目線でまとめ直したもの）。改善はこの章のチェックリストで確かめながら進める。

---

## 1. 入力に関わるルール（04 章の要点）

### 1.1 席と人数

| 人数 | 席（プリフロップのアクション順） | 備考 |
|---|---|---|
| 6 | UTG → HJ → CO → BTN → SB → BB | |
| 5 | HJ → CO → BTN → SB → BB | 早い席から削る |
| 4 | CO → BTN → SB → BB | |
| 3 | BTN → SB → BB | |
| 2 | BTN → BB | **BTN が SB を払う**。プリフロップは BTN から、フロップ以降は BB から |

- フロップ以降の順は SB → BB → UTG → HJ → CO → BTN（フォールドした席を飛ばす）。ヘッズアップは BB → BTN。
- ブラインド: SB（ヘッズアップは BTN）が SB、BB が BB を払う。アンティは座っている全員。

### 1.2 1 手ごとに取れるアクション

| 状況 | 取れるアクション |
|---|---|
| 誰もベットしていない（フロップ以降）／BB のオプション（リンプされた BB） | チェック、ベット（BB 以上。レイズの形は「レイズ」） |
| ベットがある | フォールド、コール、レイズ |
| スタックがコール額以下 | フォールド、コール（オールイン） |
| 他に動ける人がいない（全員オールイン） | ベット・レイズはできない |

- 額は **「to」（そのストリートでの合計）**で入れる。レイズ 2.5 → 7.5 の「7.5」。
- 最小レイズ: 直前の有効なレイズ幅以上（最初は BB）。オールインはそれ未満でもよい（不完全レイズ）。
- 不完全レイズはアクションを再オープンしない（既にアクションした人はレイズできない）。

### 1.3 ストリートの進行とボード

- 全員のベットがそろう → 次のストリート。フロップ 3 枚・ターン 1 枚・リバー 1 枚。
- 残り 1 人 → そこで終了（ポット獲得）。
- オールインで動ける人が 1 人以下 → 残りのボードを出して終了（ランアウト）。
- リバーのアクションが終わる → ショーダウン。

### 1.4 WWYD 固有の決まり

- スポットは **Hero のフロップ以降のアクション**だけ（04 章 §8.1）。フロップまで進まないハンドは投稿できない。
- ハンドは最後まで入れる（Villain の実際のアクションを見せるため）。
- 分かっているハンドだけ入れる（入れていない席はマック）。

## 2. 入力する人が頭の中で考えていること

ハンドを思い出して書くとき、プレイヤーは次の言葉で考える。入力はこの言葉の順番・単位に合わせる。

| 考えていること | 例 | 入力への要求 |
|---|---|---|
| **フォールドは「〜まで回った」** | 「CO まで降りて BTN がオープン」 | 途中のフォールドを 1 人ずつ押させない。「BTN まで飛ばす」 |
| **オープンは bb で** | 2 / 2.2 / 2.5 / 3bb | よく使う額をボタンで。自由な額も入れられる |
| **3bet・4bet は倍率で** | 「3 倍」「IP は 3 倍、OOP は 4 倍」 | 直前のレイズの ×3・×4 などをボタンで |
| **フロップ以降のベットは % pot で** | 33% / 50% / 75% / ポット / オーバーベット | % pot のボタン。額（bb）も同時に見える |
| **レイズは倍率で** | 「2.5 倍レイズ」「3 倍」 | 直前のベットの ×2.5・×3 |
| **オールイン** | 「ジャム」「シップ」 | 1 回で入る |
| **チェック・コールは迷わない** | 「BB チェック、BTN ベット、BB コール」 | チェックとコールは同じ場所（取れる方だけ出る） |
| **今どこか** | 「ターンで BB の番、ポット 22bb」 | 手番・ストリート・ポット・to call を 1 か所で |
| **間違えたら 1 手戻す** | | 1 つ戻すは常に同じ場所 |
| **ボードはストリートの切れ目に** | 「フロップ K83r」 | ストリートが終わったら自動でカードを選ばせる |

## 3. 良い入力のチェックリスト（試験で確かめる）

| # | 観点 | 合格の基準 |
|---|---|---|
| C-1 | タップ数 | 典型的なシングルレイズドポット（6 人・リバーまで）が 25 タップ以内 |
| C-2 | フォールドの連続 | 「X まで飛ばす」が 1 タップ |
| C-3 | 額 | よく使う額はキーボードを出さずに入る。% pot と bb が並んで見える |
| C-4 | ボタンの位置 | 押すボタンの位置が手番ごとに動かない（同じ指の位置で続けて押せる） |
| C-5 | 取れないアクション | 取れないアクションは押せない。チェックとコール、ベットとレイズは同じ場所 |
| C-6 | 状況 | 手番・ストリート・ポット・to call・残りスタックが一目で分かる |
| C-7 | 戻す | 1 つ戻すが常に届く位置 |

## 5. 試行錯誤の記録

試験はスマホの幅（412×915・375×667）で、開発サーバーの画面を利用者と同じ操作（ボタンを押す）で入力して行った。
タップ数は、アクション・額・ボードのカードを押した回数（キーボードで額を打つときは 1 文字 1 タップ＋欄を押す 1 タップ）。

### 5.1 作り直す前（2026-09-29）

P-1 を入れて **35 タップ**（額は 4 回ともキーボードで打つ）。見つかった問題:

| # | 問題 | チェック |
|---|---|---|
| B-1 | UTG・HJ・CO のフォールドを 1 人ずつ押す | C-2 |
| B-2 | 額の初期値がオープン 2bb（最小）・ベット 50% で、2.5bb や 33% はキーボードで打つしかない | C-3 |
| B-3 | 「チェック」と「コール」、「ベット」と「レイズ」が別のボタンで、どちらかが必ず非活性（5 つのうち 2 つは常に押せない） | C-5 |
| B-4 | 状況行にポットが無い | C-6 |
| B-5 | ボタンが画面の中ほど。スマホで親指が届きにくく、ログが伸びると位置が変わる | C-4 |
| B-6 | ボードのカードピッカーのボタンに名前が無い（読み上げで札が分からない） | — |

### 5.2 作り直した内容

- アクションの台（スマホは画面の下に固定）: 手番の見出し（席・ストリート・POT・残り・1つ戻す）→ よく使う額 →
  Fold to / Check to と額の入力欄 → 3 つのボタン（フォールド / チェック・コール / ベット・レイズ {額}）。
- よく使う額はプレイヤーが考える単位（オープン bb・3bet ×倍率・ベット % pot・レイズ ×倍率・オールイン）。% pot は 0.1bb に丸める。
- カードピッカーのボタンに札の名前（「K♥」）を付けた。

### 5.3 作り直した後の試験

| パターン | タップ数 | 確かめたこと |
|---|---|---|
| P-1 | **20**（前 35） | Fold to BTN の 1 タップ、オープン 2.5 は既定のまま、33% は既定・75% / 100% は 1 タップ。キーボードを 1 回も出さない |
| P-2 | 20 | 3bet ×3・フロップのチェックレイズ ×3、Fold to で SB・BB をまとめて |
| P-3 | 21 | リンプ 2 人＋SB コンプリートの後、BB のアイソレートは 6 / 7 / 8bb。フロップ Check to HJ で SB・BB のチェックを 1 タップ |
| P-4 | 15 | 3bet 11bb は入力欄に打つ（自由な額）。オールインのボタンで「レイズ 100 オールイン」。コールの後、フロップ・ターン・リバーのピッカーが続けて開く |
| P-5 | 12 | ヘッズアップ: プリフロップ BTN（to call 0.5）から、フロップ以降 BB から |
| P-6 | 11 | MTT・アンティ 0.12・5 人・ショート: POT 2.1（アンティ 5 人分）、BB のオールインは 14.88、HJ はレイズできない |

試験の途中で見つけて直したもの:

| # | 問題 | 直した内容 |
|---|---|---|
| F-1 | 相手のオールインでレイズできないとき、3 つ目のボタンが「ベット」と出る | ベットがあるとき（BB のオプションを含む）は「レイズ」と出して非活性 |
| F-2 | 375px 幅で見出しの数字が 2 行になる | to call はコールのボタンに出ているので見出しから外した（POT・残りだけ） |
| F-3 | 額の入力欄がよく使う額の列を狭め、「オールイン」が切れる | よく使う額は 1 行を使い、入力欄は Fold to の行の右へ |
| F-4 | 1つ戻すでプリフロップまで戻ると、ボードが 5 枚とも出ていて進んだように見える | まだ来ていないストリートのカードを薄く出す |
| F-5 | % pot の額が 1.82 や 22.86 のように細かく、ログが読みにくい | % pot は 0.1bb に丸める |

### 5.4 残した判断 → 2026-09-30 さつきの確認で、この形のまま確定

- ログのコールの額は「追加で出した額」（PokerStars のハンドヒストリーと同じ）。レイズ・ベットは to。
- よく使う額の種類と、最初に選んでおく額（オープン 2.5・3bet ×3・ベット 33%・レイズ ×3）。
- 1つ戻すは 1 手ずつ（Fold to でまとめて入れた分も 1 手ずつ戻る）。

## 6. 類似アプリの調査の反映（2026-09-29。14 章）

- 入力中のハンドを卓で出す（Hero を手前、手番の席を光らせる、スタック・ベット・ポット・ボード）。ボードの枠は卓の中。
- ログの 1 手を押すと、確認のあと、その手から後のアクションを消して入れ直せる（ボードは残す）。
- 台のボタンの名前を局面に合わせる: プリフロップ「オープン」（リンプがいれば「レイズ」）→「3bet」→「4bet」…、
  レイズの無いプリフロップの BB 以外のコールは「リンプ」。フロップ以降「ベット」→「レイズ」→「3bet」…。
  ログとハンドヒストリーの表記は変えない（レイズ・コール）。
- さつきの確認を受けて（14 章 §3.1）: スマホのログはモーダル（「ヒストリー」）、台は「道具の行」（手番・1つ戻す・1つ進む・すべて消す・額）に
  まとめて見出しの行を無くした、スマホの額は縦のスライダー。
